# Security Policy

## Supported versions

Security fixes are currently considered for the active v0.1 release line.

| Version | Supported |
| --- | --- |
| 0.1.x | Yes |
| Earlier versions | No |

## Reporting a vulnerability

Please report suspected vulnerabilities privately. Use GitHub private
vulnerability reporting through the repository's **Security** tab when the
**Report a vulnerability** option is available, or email the maintainer at
[lisafronaldio123@gmail.com](mailto:lisafronaldio123@gmail.com).

Include enough detail to investigate safely:

- the affected ReviewLens version and environment;
- the vulnerability's impact and realistic threat model;
- minimal reproduction steps or a proof of concept;
- affected inputs, configuration, and output behavior; and
- any mitigations or fixes you have already identified.

Remove personal data, credentials, and unrelated sensitive content from the
report. If sensitive attachments are necessary, ask the maintainer to agree on
a safe transfer method first.

The maintainer will acknowledge receipt, investigate, and coordinate next steps
with the reporter. ReviewLens does not promise a fixed response-time or
resolution-time service level. Please do not disclose the vulnerability in a
public issue, discussion, pull request, social post, advisory, or other public
channel before coordinated disclosure has been agreed with the maintainer.

This process is for security vulnerabilities. Ordinary defects and feature
requests can use the repository's public issue tracker.
